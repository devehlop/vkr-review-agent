> Приоритеты требований: **M** — обязательно (must), **S** — желательно (should), **C** — если останется время (could).

## 1. Назначение и цель

**Система:** LLM-агент, который анализирует отзывы покупателей на товар продавца и на товары конкурентов и формирует обоснованные рекомендации по развитию товара.

**Цель:** сократить время, которое продавец тратит на ручной разбор отзывов, и перейти от описания проблем («ругают упаковку») к конкретным действиям («заменить пакет на коробку: 18 % негативных упоминаний, у конкурента А такой проблемы нет»).

**Отличие от аналогов** (см. `docs/analogs.md`): существующие решения описывают отзывы, а агент выдаёт приоритизированные рекомендации со ссылками на отзывы и сравнением с конкурентами.

## 2. Пользователь и сценарии

**Пользователь:** продавец или менеджер товара на Wildberries или Ozon. Не аналитик данных, читает отчёт, а не таблицы.

**Основной сценарий (M):**
1. Продавец загружает отзывы на свой товар (файл выгрузки или по артикулу).
2. Добавляет отзывы на 1–3 товара конкурентов (по желанию).
3. Выбирает период (например, последние 6 месяцев).
4. Получает отчёт: сильные стороны, проблемы, сравнение с конкурентами, рекомендации по приоритету.
5. Открывает примеры отзывов для любого вывода.

**Дополнительные сценарии:**
- (S) Задать агенту вопрос по отзывам: «Что говорят про размер?», «Почему упал рейтинг в сентябре?».
- (C) Сравнить два периода: стало ли лучше после изменения товара.

## 3. Входные данные

| Источник | Приоритет | Комментарий |
|---|---|---|
| Файл CSV/XLSX (выгрузка отзывов) | M | Ozon Seller позволяет выгружать отзывы в Excel. Минимальные поля: текст, оценка, дата. Дополнительно: достоинства, недостатки, вариант товара (цвет/размер) |
| Открытые датасеты (RuReviews) | M | Для отладки и оценки качества |
| API продавца WB/Ozon | C | Только свои товары. Проверить, какие методы для отзывов есть в API |
| Отзывы конкурентов | S | Через файл. Автоматический сбор только после проверки правил площадок |

Ограничение: персональные данные покупателей (имена, фото) не обрабатываются и не хранятся.

## 4. Функциональные требования

### 4.1. Загрузка и предобработка
- **FR-1 (M)** Загрузка отзывов из CSV/XLSX с сопоставлением колонок.
- **FR-2 (M)** Очистка: пустые отзывы, дубликаты, служебные символы. Поля «достоинства / недостатки / комментарий» объединяются с пометкой источника.
- **FR-3 (M)** Разбиение отзыва на предложения. Анализ идёт по предложениям, это точнее, чем по отзыву целиком (Boughanmi et al., 2025).
- **FR-4 (S)** Отметка подозрительных отзывов (однотипные тексты, возможные самовыкупы). Они не удаляются, а учитываются отдельно.

### 4.2. Аспектный анализ
- **FR-5 (M)** Извлечение аспектов по двухуровневой схеме: **атрибут** (например, «Качество») → **признак** (например, «швы расходятся»).
- **FR-6 (M)** Тональность каждого упоминания по трёхбалльной шкале: негатив, нейтрально, позитив.
- **FR-7 (M)** Справочник атрибутов для категории: генерируется агентом по выборке отзывов и может быть отредактирован пользователем.
- **FR-8 (M)** Агрегация: число упоминаний, доля от всех отзывов, распределение тональности по каждому атрибуту и признаку.
- **FR-9 (S)** Динамика по времени: как меняется доля негатива по атрибуту по месяцам.

### 4.3. Проблемы и сравнение
- **FR-10 (M)** Группировка негативных упоминаний в проблемы (кластеризация близких формулировок).
- **FR-11 (M)** Для каждой проблемы: формулировка, частота, доля, 3–5 характерных отзывов.
- **FR-12 (S)** Сравнение с конкурентами по атрибутам: где товар лучше, где хуже, каких проблем у конкурентов нет.

### 4.4. Рекомендации
- **FR-13 (M)** Генерация рекомендаций по каждой значимой проблеме и по сильным сторонам (что подчеркнуть в карточке товара).
- **FR-14 (M)** Каждая рекомендация содержит: действие, на какую проблему направлено, обоснование (доля упоминаний, примеры отзывов), тип (товар, упаковка, карточка товара, логистика, размерная сетка).
- **FR-15 (M)** Шаг проверки: отдельный агент-критик проверяет конкретность, обоснованность и выполнимость рекомендации и возвращает на доработку (Bhandari et al., 2026).
- **FR-16 (M)** Приоритизация: по частоте проблемы, силе негатива и сложности исправления.
- **FR-17 (M)** Запрет выдумывать: вывод без опоры на отзывы не попадает в отчёт.

### 4.5. Отчёт и интерфейс
- **FR-18 (M)** Отчёт: краткое резюме, сильные стороны, проблемы, сравнение с конкурентами (если есть), рекомендации по приоритету.
- **FR-19 (M)** Веб-интерфейс: загрузка файлов, настройка, просмотр отчёта, переход к примерам отзывов.
- **FR-20 (S)** Экспорт отчёта в DOCX или PDF.
- **FR-21 (S)** Вопросы агенту по отзывам в свободной форме (ответ со ссылками на отзывы).

## 5. Нефункциональные требования

- **NFR-1 (M) Язык:** интерфейс, отчёт и анализ на русском, в том числе разговорной речи и опечаток.
- **NFR-2 (M) Скорость:** до 1 000 отзывов обрабатываются не дольше 15 минут. Значение уточнить после замеров на этапе MVP.
- **NFR-3 (M) Стоимость:** стоимость анализа 1 000 отзывов считается и выводится в журнале. Целевое значение определить после выбора LLM.
- **NFR-4 (M) Замена модели:** LLM подключается через единый интерфейс, модель меняется настройкой без переписывания кода.
- **NFR-5 (M) Воспроизводимость:** фиксированные параметры генерации, промпты в отдельных файлах с версиями, журнал всех запросов к LLM.
- **NFR-6 (M) Надёжность:** повтор запроса при ошибке, проверка формата ответа модели по схеме, пропуск битых записей с отметкой в журнале.
- **NFR-7 (M) Конфиденциальность:** ключи API в переменных окружения, персональные данные не хранятся.
- **NFR-8 (S) Тесты:** модульные тесты на предобработку и агрегацию, интеграционный тест на маленькой выборке.

## 6. Оценка качества

Без оценки качества защищать нечего, поэтому это обязательная часть (M).

| Что оцениваем | Как | Метрика |
|---|---|---|
| Извлечение аспектов | Эталонная выборка: 300 предложений, размеченных вручную | Precision, Recall, F1 |
| Тональность | Та же выборка | Accuracy, macro-F1 |
| Согласованность с человеком | Две разметки одной выборки (вы и второй человек, если получится) | Каппа Коэна или α Криппендорфа |
| Рекомендации | Экспертная оценка 20–30 рекомендаций по шкале 1–5: конкретность, обоснованность, выполнимость | Средний балл |
| Рекомендации (дополнительно) | LLM-судья по тем же критериям, сравнение с экспертом | Корреляция оценок |
| Вклад агента-критика | Сравнение рекомендаций с проверкой и без неё | Разница средних баллов |

Базовая линия для сравнения: готовая модель тональности RuBERT (для тональности) и одиночный промпт без агентной схемы (для рекомендаций).

## 7. Принятые решения (27.10.2026)

| Вопрос | Решение | Почему |
|---|---|---|
| LLM | Российская облачная модель как основная + открытая модель для сравнения. Кандидаты: GigaChat 2 (Pro/Max), YandexGPT 5.1 Pro, открытая Qwen3.6. Окончательный выбор по мини-эксперименту на размеченной выборке (см. `docs/architecture.md`, раздел 4) | Хороший русский язык, оплата из России, у GigaChat есть бесплатный лимит для физлиц. Сравнение моделей усиливает исследовательскую часть ВКР |
| Оркестрация агента | Свой код на Python, без фреймворка | Каждый шаг прозрачен и легко объясняется на защите, меньше зависимостей |
| Интерфейс | Streamlit | Быстро и удобно для демонстрации |
| Хранилище | SQLite | Не требует сервера, один файл |
| Основной источник данных | Выгрузка из файла + RuReviews для оценки | Законно и не зависит от API площадок |
| Категория товаров для демонстрации | Одежда | Совпадает с RuReviews, много аспектов (размер, ткань, швы) |

## 8. Ограничения и допущения

- Система даёт рекомендации, а решение принимает продавец.
- Качество зависит от числа отзывов. Для товара с менее чем ~30 отзывами отчёт выдаётся с предупреждением.
- Автоматический сбор отзывов конкурентов не входит в обязательную часть.
- Связь рекомендаций с ростом продаж не проверяется, это выходит за рамки работы.

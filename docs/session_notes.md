### Как запускать (Mac, zsh, из корня репозитория)
```bash
git pull && pip install requests jsonschema openpyxl razdel numpy sentence-transformers pytest
export GIGACHAT_CA_BUNDLE="$HOME/Downloads/russian_ca_bundle.pem"   # оба корневых сертификата Минцифры в одном файле
read -s "GIGACHAT_CREDENTIALS?Ключ авторизации: "; export GIGACHAT_CREDENTIALS; echo
python scripts/run_taxonomy.py data/synthetic_reviews.csv --product "Куртка" --category "женская одежда" --out data/taxonomy_synthetic_v2.json
python scripts/run_extract.py   data/synthetic_reviews.csv --product "Куртка" --taxonomy data/taxonomy_synthetic_v2.json
python scripts/run_aggregate.py data/synthetic_reviews.csv --product "Куртка" --mentions data/mentions.json --taxonomy data/taxonomy_synthetic_v2.json
python scripts/run_issues.py    data/synthetic_reviews.csv --product "Куртка" --taxonomy data/taxonomy_synthetic_v2.json --mentions data/mentions.json
```
Переменные нужно задавать в каждом новом окне терминала. Ключ вводится только скрытой командой `read -s`, не в чат и не в команду. Кэш и журнал вызовов: `.cache/llm.sqlite` (в `.gitignore`, содержит тексты отзывов). Выходные файлы `data/taxonomy_*.json`, `mentions.json`, `aggregate.csv`, `issues.json` лежат только на компьютере студента и в репозиторий не добавлены.

### Важные решения и находки
- **Облачная сессия не видит GigaChat** (502 и сброс соединения), реальные запуски только у студента локально; в облаке всё проверяется на заглушках (`FakeLLMClient`, `FakeEmbedder`).
- **Выбран REST, а не gRPC** (файл `gigachat.proto` не использовали).
- **Эмбеддинги GigaChat недоступны в бесплатном пакете** (HTTP 402, квота отдельная), поэтому по умолчанию локальная модель `intfloat/multilingual-e5-small` (`--embedder local`); GigaChat-вариант оставлен флагом `--embedder gigachat`.
- **Сбой надёжности шлюза** (для главы): GigaChat иногда пропускает закрывающие скобки в JSON (`]]}` вместо `}]}]}`, `finish_reason=stop`), повторы при росте температуры ответ не меняли. Лечится починкой скобок стеком; сначала была неверная гипотеза про обрыв ответа, опровергнутая диагностикой. Подробности в `docs/thesis/materials_reliability.md`.
- **Находка по данным:** в цитатах проблем смешивались аспекты, потому что пункты в полях «Достоинства/Недостатки» перечислены через «;». Исправлено разбиением по «;».
- Промпты лежат в `src/review_agent/prompts/` с версией в имени; менять = создавать новую версию.
- Порядок поддержки признаков: пока извлекаются только **атрибуты**; признаки внутри атрибута (FR-5, FR-8 на уровне признаков) не реализованы.

### Долги и ограничения
- Все прогоны на **синтетике** (`data/synthetic_reviews.csv`, 54 выдуманных отзыва на куртку). Для выводов в дипломе нужна реальная выгрузка отзывов (без имён авторов) в `data/`; пока её нет.
- Порог подозрительных отзывов (0,8) и порог кластеризации (0,35, для e5 возможно другой) не подобраны на реальных данных. Пробовать `--threshold 0.15 / 0.25 / 0.35`.
- Качество разметки аспектов и тональности не оценено: нужна ручная проверка 10–15 упоминаний, затем эталонная разметка по методике из раздела 6 `docs/tz.md`.
- Мини-эксперимент по выбору LLM (GigaChat / YandexGPT / Qwen) из этапа 3 роадмапа не сделан.
- В `docs/ai_log.md` колонка «что изменено вручную» везде пустая: студент заполняет её сам после вычитки кода и текстов.
- Статистику токенов неудачных вызовов журнал пишет нулями, цифры стоимости по сбойным вызовам занижены.
- **Ключи, показанные в чате, считать скомпрометированными.** Студент сообщил, что перевыпустил ключ и записал новый.

### Следующие шаги (по порядку)
1. **Шаги 8–9: рекомендации и «критик».** Генератор: проблема, статистика, цитаты, данные конкурентов → 1–2 действия (действие, тип: товар / упаковка / карточка товара / размерная сетка / логистика, обоснование, ожидаемый эффект, сложность 1–3); отдельно рекомендации по сильным сторонам для карточки товара. Критик: конкретность, опора на отзывы, выполнимость, отсутствие повтора; до 2 доработок; непрошедшие остаются в журнале. Запуск с критиком и без него для оценки вклада.
2. Шаг 10: приоритизация `P = охват × доля негатива × K_конк / сложность`.
3. Шаг 11: проверка опоры (ссылки на проблемы, цитаты — подстроки предложений; у проблем уже есть `review_ids` и цитаты).
4. Шаг 12: отчёт (DOCX/PDF) и интерфейс (Streamlit по решению в `tz.md`).
5. Шаг 7: сравнение с конкурентами, когда появятся отзывы конкурента (библиотека агрегации уже считает по товарам раздельно).
6. Реальная выгрузка отзывов → прогон цепочки → подбор порогов → оценка качества.

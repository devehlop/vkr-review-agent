# Инструкция по разметке

> **Статус:** черновик, подготовлен с помощью ИИ 19.11.2026. Перед разметкой прочитать, поправить правила под себя и отметить в `docs/ai_log.md`. Правила, которые меняются по ходу разметки, дописывать в раздел «Спорные случаи», чтобы разметка была одинаковой от начала до конца.

## Что размечаем

Для каждого **предложения** (колонка `sentence`) отмечаем, какие **атрибуты** товара в нём упомянуты и с какой тональностью. Полный текст отзыва (`review_text`) дан для контекста: по нему можно понять, о чём речь, но размечаем только то, что сказано в самом предложении.

В колонке атрибута ставим:

| Значение | Когда |
|---|---|
| `-1` | Атрибут упомянут негативно: недостаток, жалоба, разочарование |
| `0` | Упомянут нейтрально или неоднозначно: факт без оценки («брала размер S»), «нормально», «пойдёт» |
| `1` | Упомянут позитивно |
| пусто | Атрибут не упомянут |

Колонки:
- `features` — по желанию: признак из справочника (например, `маломерит`) или свой, если подходящего нет. Несколько через `;`.
- `note` — сомнения, спорный случай, предложение добавить признак в справочник.
- `review_label` — класс отзыва из датасета, получен автоматически по оценке покупателя. Это **не** подсказка: предложение из негативного отзыва может быть позитивным.

## Атрибуты (справочник `clothing_v1`)

| Код | Атрибут | Сюда относится |
|---|---|---|
| `size` | Размер и посадка | маломерит / большемерит, размерная сетка, длина, рукава, как села по фигуре |
| `fabric` | Ткань и материал | синтетика / хлопок, тонкая / плотная, приятная к телу, просвечивает, мнётся |
| `sewing` | Качество пошива | швы, нитки, дырки, брак, молнии и пуговицы, запах |
| `look` | Внешний вид и цвет | цвет, принт, фасон, «красивое», «смотрится дёшево» |
| `match` | Соответствие описанию и фото | «как на фото», «не соответствует описанию», «на картинке ярче» |
| `durability` | Носкость и уход | после стирки, линяет, катышки, села или растянулась |
| `price` | Цена | цена/качество, «за такие деньги», дорого / дёшево |
| `delivery` | Доставка | сроки, не пришёл, трек |
| `packaging` | Упаковка | упаковка, помялось или повредилось в пути |
| `seller` | Продавец и сервис | общение, спор, возврат денег, прислали не тот размер или цвет, подарки от продавца |
| `overall` | Общее впечатление | «рекомендую», «довольна», «не советую», «ужас» без указания, что именно плохо |

## Правила

1. **Одно предложение — сколько угодно атрибутов.** «Ткань тонкая, но цвет красивый» → `fabric = -1`, `look = 1`.
2. **Без атрибутов — тоже ответ.** Если в предложении нет ничего о товаре или сервисе («Заказывала маме»), все колонки пустые. Такие предложения нужны, чтобы проверять, не выдумывает ли модель упоминания.
3. **`overall` только когда нет конкретики.** «Отличное платье, рекомендую» → `overall = 1`. «Отличное платье, ткань приятная» → `fabric = 1`, а `overall` ставить, только если есть отдельная общая оценка («отличное платье»).
4. **Сравнение с фото — в `match`, а сам признак — в свой атрибут.** «Цвет бледнее, чем на фото» → `match = -1`, `look = -1`.
5. **Не тот размер прислали** — это `seller`, а не `size`. **Размер не подошёл** — `size`.
6. **Иносказания и сарказм размечаем по смыслу.** «Только дома убираться в этом платье» → негатив.
7. **Факт без оценки — `0`.** «Брала L на рост 165» → `size = 0`. А «L подошёл на рост 165» → `size = 1`.
8. **Смешанная оценка одного атрибута** («ткань приятная, но тонковата») → по главному смыслу; если не понять, `0` и пометка в `note`.

## Порядок работы

1. Сначала `fewshot` (30 предложений): на нём привыкнуть к правилам и дописать спорные случаи.
2. Потом `mini` (100): нужен для мини-эксперимента по выбору модели.
3. `test` (300) — позже, до этапа оценки качества (январь).
4. Желательно, чтобы `mini` разметил ещё один человек независимо, не видя первой разметки: по двум разметкам считается согласованность (каппа Коэна, раздел 6 ТЗ).

Размеченные файлы сохранять под тем же именем в `data/annotation/`: XLSX читается программой напрямую.

## Как считаем качество

- **Аспекты:** пара (атрибут, предложение) — precision, recall, F1 (micro и по атрибутам).
- **Тональность:** на парах, которые нашли и человек, и модель, — accuracy и macro-F1.
- **Строгий вариант:** тройка (атрибут, тональность, предложение) совпадает целиком — F1.
- Признаки (`features`) в метриках пока не участвуют: справочник признаков модель строит сама, сравнивать их напрямую нельзя.

Код метрик (precision, recall, F1, macro-F1, каппа Коэна) есть в PR #2 и будет перенесён отдельной веткой вместе со скриптом мини-эксперимента.

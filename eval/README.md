# Мини-эксперимент: выбор LLM

Цель: сравнить GigaChat, YandexGPT и открытую модель Qwen на задаче извлечения аспектов и тональности (шаг 4 конвейера) и выбрать основную модель.

## Что есть

- `data/eval/sample_100.csv`: 100 предложений из RuReviews (34 из нейтральных отзывов, по 33 из негативных и позитивных, случайная выборка с seed=42). Колонка «разметка» пустая.
- `eval/taxonomy_clothing.json`: справочник из 11 атрибутов для одежды.
- `eval/prepare_sample.py`: пересобирает выборку из файла датасета.
- `eval/run_experiment.py`: прогоняет модели и считает метрики.

## Шаг 1. Разметить выборку вручную

Открыть `data/eval/sample_100.csv` в Excel или LibreOffice (разделитель «;», кодировка UTF-8) и заполнить колонку «разметка» в каждой строке.

Формат:

| Что в предложении | Что писать |
|---|---|
| Одно упоминание | `Размер и посадка=-1` |
| Несколько упоминаний | `Ткань и материал=1; Качество пошива=-1` |
| Нет характеристик из справочника | `-` |

Тональность: `-1` негатив, `0` нейтрально (факт без оценки), `1` позитив.

Правила разметки:

1. Названия атрибутов писать точно как в справочнике. Программа сообщит о строке с ошибкой.
2. Размечать только то, что сказано в самом предложении, без догадок по остальному отзыву. Колонка «тональность_отзыва» относится ко всему отзыву и для предложения может не подходить.
3. Один атрибут в предложении указывается один раз. Если о нём сказано и хорошее, и плохое, выбрать преобладающее, при равенстве `0`.
4. «Маломерит», «большемерит», «подошёл размер» относятся к «Размер и посадка».
5. «Как на фото», «не соответствует описанию», «прислали другое» относятся к «Соответствие описанию».
6. Оценка без конкретной характеристики («всё отлично», «ужас», «рекомендую») относится к «Общее впечатление».
7. Предложение о покупателе, а не о товаре («заказывала дочке») размечается как `-`.
8. Спорные случаи записывать отдельно: они пригодятся в главе 3 как примеры сложных предложений.

Разметка занимает примерно час. Её должен делать человек: если эталон составит языковая модель, сравнение моделей с ним теряет смысл.

## Шаг 2. Получить ключи и вписать их в `.env`

Скопировать `.env.example` в `.env` и заполнить.

- **GigaChat:** зарегистрироваться на developers.sber.ru, создать проект GigaChat API, взять ключ авторизации (Authorization key). Для соединения нужен сертификат НУЦ Минцифры: путь к нему указать в `GIGACHAT_CA_BUNDLE`.
- **YandexGPT:** в Yandex Cloud создать каталог и API-ключ сервисного аккаунта с ролью для работы с языковыми моделями. Нужны идентификатор каталога и ключ.
- **Qwen:** либо локально через Ollama (тогда `QWEN_MODEL` это имя скачанной модели), либо облачный сервер с OpenAI-совместимым API (тогда указать его адрес, модель и ключ).

Цены за 1000 токенов вписать из актуальных тарифов, иначе стоимость будет нулевой.

Запускать можно с теми моделями, для которых ключи уже есть.

## Шаг 3. Запустить

```bash
python -m eval.run_experiment --models gigachat
```

```bash
python -m eval.run_experiment --models gigachat yandex qwen
```

Результат: таблица в `eval/results/` (Markdown и JSON), журнал всех запросов в `logs/`. Повторный запуск берёт ответы из кэша `.cache/` и ничего не стоит. Чтобы запросить модель заново, удалить папку `.cache/`.

## Что считается

| Показатель | Смысл |
|---|---|
| Precision, Recall, F1 по аспектам | Совпадение пар «предложение, атрибут» с эталоном |
| Accuracy и macro-F1 по тональности | На парах, где атрибут найден верно |
| Доля ошибок формата | Ответы, не прошедшие проверку: не JSON, атрибут не из справочника, выдуманная цитата |
| Предложений без ответа | Пакеты, которые модель не смогла исправить за две попытки |
| Токены, стоимость, время | Расход на всю выборку |

## Ограничения, о которых надо написать в ВКР

- 100 предложений дают грубую оценку: разница в несколько процентных пунктов между моделями может быть случайной. Основная оценка качества будет на 300 предложениях (раздел 7.2 ТЗ).
- Разметчик один, согласованность между разметчиками не измерена.
- Сравнивается один вариант промпта без примеров (zero-shot).
